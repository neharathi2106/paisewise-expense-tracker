# Paisewise: AI-Powered Expense Tracker

Paisewise is a B.Tech Computer Science and Engineering Design and Analysis of Algorithms (DAA) problem-based learning project. It is a local Streamlit application for recording expenses, reviewing spending patterns, managing a monthly budget, demonstrating sorting and searching algorithms, and estimating a following month's spending from recorded monthly totals.

## Problem statement

A list of purchases can be difficult to summarize by category or month. Manual totals take effort, and a user may notice budget pressure late. Paisewise keeps a searchable local ledger and calculates visible summaries from the saved records.

## Objectives

- Store dated expenses persistently and support create, read, update, and delete operations.
- Show lifetime and current-month spending, transaction averages, and category/month summaries.
- Store a monthly budget and display progress and budget warnings.
- Implement Merge Sort, Bubble Sort, and Binary Search manually for DAA demonstration.
- Compare sort execution times on equivalent copies of a dataset.
- Demonstrate a scikit-learn regression forecast based on actual monthly expense totals.

## Features

- Dark navy and indigo Streamlit interface with nine pages: Dashboard, Add Expense, Transactions, Analytics, Budget Planner, AI Spending Insights, ML Expense Prediction, DAA Lab, and About Project.
- SQLite persistence for expenses and one monthly budget setting.
- Expense title search, category and date filters, sorting, editing, and deletion after confirmation.
- Daily, monthly, and category-based analytics using recorded data.
- Rule-based spending insights. These calculations are separate from the ML prediction feature and are not generated by a large language model.
- Manual Merge Sort, early-terminating Bubble Sort, and duplicate-aware Binary Search.
- Runtime comparison using `time.perf_counter()` on recorded values or deterministic synthetic values. Synthetic values are not written to the database.
- Linear Regression prediction with chronological holdout MAE when enough monthly history exists.

## Installation and launch on macOS

Clone the repository after it is published. Replace the placeholder with its actual GitHub URL:

```bash
git clone https://github.com/<YOUR_GITHUB_USERNAME>/paisewise-expense-tracker.git
cd paisewise-expense-tracker

python3 -m venv .venv
source .venv/bin/activate
```

Streamlit prints a local URL, usually `http://localhost:8501`. Press **Control-C** in Terminal to stop the server. To restart, return to the project folder, activate `.venv`, and run `streamlit run app.py` again.

## Database initialization and privacy

On startup, `app.py` calls `initialize_database()`. If the database does not exist, Paisewise creates `expenses` and `settings` tables automatically. The default file is `expenses.db` beside `database.py`. Records remain in that file between app restarts.

The local database is intentionally excluded from Git because it may contain private expense information. Each clone creates its own empty database at first launch. To select another local path, set `EXPENSE_TRACKER_DB` before starting Streamlit:

```bash
export EXPENSE_TRACKER_DB="$PWD/my_expenses.db"
streamlit run app.py
```

The expense table stores an autoincrement `id`, required title, positive amount, category, ISO date, optional notes, and a creation timestamp. The settings table stores a key/value pair for the monthly budget. SQL values use parameterized queries.

## DAA algorithms

| Algorithm | Best time | Average time | Worst time | Space note |
|---|---:|---:|---:|---|
| Merge Sort | O(n log n) | O(n log n) | O(n log n) | O(n) auxiliary merge storage |
| Bubble Sort with early exit | O(n) | O(n²) | O(n²) | O(1) working space; implementation returns a copied list |
| Iterative Binary Search | O(1) | O(log n) | O(log n) | O(1) search space; matching duplicates add O(k) result space |

Merge Sort divides the list recursively and merges ordered halves. Bubble Sort compares adjacent amounts and exits when a pass makes no swaps. Binary Search requires ascending input; Paisewise sorts before searching and expands around a match to return every adjacent duplicate amount. The transaction page's sorting uses Pandas. The manual DAA algorithms run in the DAA Lab.

The performance comparison measures equivalent independent copies using `time.perf_counter()` and reports the median of the selected repetitions. Machine load, input size, and runtime overhead affect observed timing. Theoretical complexity describes growth and does not promise a specific elapsed time.

## ML expense prediction

The ML page reads expense rows, parses valid dates, and groups spending into calendar-month totals. Missing months between the earliest and latest recorded months count as zero. It does not invent months outside the observed range. Invalid dates are excluded.

The application uses scikit-learn `LinearRegression` with one feature, a sequential month index, and one target, monthly total spending. It requires at least six monthly buckets to predict the next month. With at least eight buckets, it trains a temporary model on earlier months and computes Mean Absolute Error (MAE) on later months in chronological order. The final prediction model then fits all available history. This is a simple trend extrapolation, not a guarantee of future spending or an accuracy claim.

## Known limitations

- The app is a local single-user project. It has no login, bank sync, or cloud backup.
- The budget is a single monthly amount, not a category-specific limit.
- Spending insights are transparent rules and arithmetic. The savings prompt is a heuristic.
- The forecast has only a month-index feature and may not capture seasonal or one-off spending.
- Months with no transactions inside the observed history are treated as zero.
- Runtime measurements vary by machine and dataset.

## Future scope

Possible extensions include CSV import/export, optional category budgets, recurring expense reminders, authenticated multi-user storage, encrypted backups, accessibility improvements, and richer forecasting validated on more chronological data. These are future ideas, not current features.
